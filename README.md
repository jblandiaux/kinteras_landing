# Kinteras — Landing page

Public Early Access page for Kinteras. One screen that explains the concept, one
video that proves it, one email field.

**Deliberately standalone.** Nothing here imports from `Kinetra_frontend` or calls
`Kinetra_backend`. The two shipped source assets (the wordmark, the hero clip)
were copied in once and are regenerated by a script, not linked. The game can be
rewritten without this repo noticing, and vice versa.

## Stack

React 19 · TypeScript · Vite 8 · Tailwind 4 · Framer Motion, deployed as a single
**Cloudflare Worker with static assets** — the SPA is served by the platform and
`/api/*` is routed to `worker/index.ts`, with signups stored in **D1**.

Workers rather than Pages: Cloudflare now points new projects at Workers static
assets and concentrates new capability there.

> This repo does **not** run in Docker, unlike the rest of the Kinteras solution.
> It is a Vite + Wrangler toolchain whose dev server has to run the Worker inside
> workerd to be faithful to production; a container in between would only add a
> layer to debug through.

## Running it

```bash
npm install
npx wrangler d1 execute kinteras-landing --local --file=./schema.sql   # once
npm run dev
```

`npm run dev` serves the page **and** runs the Worker with a real local D1
binding, courtesy of `@cloudflare/vite-plugin` — there is no proxy and no second
process to start. `http://localhost:5273/api/early-access` exercises the exact
code that ships.

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite + Worker + local D1 |
| `npm run build` | Type-check, then build client and Worker into `dist/` |
| `npm run deploy` | Build, then `wrangler deploy` |
| `npm run db:local` / `db:remote` | Apply `schema.sql` |
| `npm run assets:prepare` | Regenerate images from their sources (see below) |

## The endpoint

`POST /api/early-access` → `{ "success": true }`

An address already on the list also returns success. The visitor asked to be
notified and they will be, so reporting "this email already exists" would be a
failure message for something that did not fail.

It rejects a malformed address (`400 invalid_email`), an unknown consent version
(`400 invalid_consent_version`), a non-POST (`405`) and an oversized body (`413`).
A filled honeypot returns `200` and writes nothing.

### Consent is versioned, and that is load-bearing

`shared/consent.ts` holds the version string **and the exact sentence shown next
to the button**. The form renders that sentence from there, the privacy page
archives the history, and the Worker refuses any version not in the list.

A `consent_version` column that nobody validates against a frozen text proves
nothing. Do not hardcode the wording anywhere else, and do not edit a published
entry — add a new one.

Adding a purpose (news, dev updates, offers) means a new version **and asking
again**. It is never a silent widening of what v1 signers agreed to.

### Attribution

`source` is where in the product the signup happened. `utm_source` / `utm_medium`
/ `utm_campaign` are which campaign delivered the click. They are separate
columns because collapsing them loses one the moment there is a second channel.

Because a repeat submission is a no-op, attribution is **first-touch**: someone
who returns from a different campaign keeps the campaign they first arrived on.

## Assets

`npm run assets:prepare` regenerates `public/` images from two sources: the
wordmark in `assets-src/`, and the game's achievement badges (path overridable
via `SOURCE_GAME_ASSETS`). Outputs are committed, so neither CI nor the
Cloudflare build needs sharp. Re-run it only when a source changes.

The hero clip and its poster are not generated — `public/video/landing_page.mp4`
is copied from the promo folder, and the poster was extracted from its first
frame with ffmpeg:

```bash
ffmpeg -i public/video/landing_page.mp4 -frames:v 1 -f image2 /tmp/poster.png
```

The poster is the clip's **first** frame on purpose: there is no visual jump when
playback starts, and under reduced motion it is the only thing that ever renders.

## Deploying — first time

The steps below need a Cloudflare login, so they are yours to run.

```bash
npx wrangler login
npx wrangler d1 create kinteras-landing        # copy database_id into wrangler.jsonc
npm run db:remote                              # create the table
npm run deploy
```

Then, in the Cloudflare dashboard:

1. **Custom domain** — attach `kinteras.app` to the Worker.
2. **Rate limiting** — add a rule on `/api/early-access`. There is deliberately no
   application-level throttle: it would mean carrying state for an endpoint that
   writes one row, and the edge does it better.
3. **Web Analytics** — enable it for the domain and paste the beacon snippet into
   `index.html`. Cookieless, so it needs no consent banner.

### Before the domain goes live

`src/pages/Privacy.tsx` opens with three constants that **must** be filled in.
They are the facts a privacy notice cannot be written without and none can be
inferred from the code:

- `CONTROLLER` — who is legally answerable. Full name, or company + registration number.
- `CONTACT` — a mailbox that is actually monitored on a domain you control.
- `RETENTION` — how long an address is kept if Early Access never opens.

## Reading the list

```bash
npx wrangler d1 execute kinteras-landing --remote \
  --command "SELECT email, created_at, utm_source FROM early_access_signup ORDER BY created_at DESC"
```

Conversion rate is that row count against the Web Analytics page-view count. No
event pipeline is wired up: `early_access_submit` and `video_visible` would be
infrastructure built ahead of any traffic to justify it.

## Layout notes worth knowing before editing

**The signup form sits above the video.** The clip is 496×1080 — roughly 1:2.18 —
so at full content width on a 375px phone it is ~712px tall, and anything under
it starts well below the fold. Wordmark, headline, pitch and form come to ~530px,
which keeps the CTA on the first screen and lets the video crest the fold just
enough to invite the scroll.

**The video is sized by height, not width** (`h-[min(58vh,540px)]`, width from the
aspect ratio). A width-driven box re-creates the overflow at every breakpoint.

**The clip is never fetched until it is nearly in view**, and never at all under
`prefers-reduced-motion` — `src` is assigned from an IntersectionObserver, because
both a plain `src` and `preload="metadata"` already let the browser start pulling
the megabyte down.
